Model 1

Matrix Factorization (BPR)

How it works

Each user and item gets a 64-dimensional embedding. The predicted score is their dot product:

// Predict user-item affinity
score(u, i) = dot(eu, ei)

Trained with BPR loss (Bayesian Personalized Ranking):

// Push positive above negative
L = -log sigmoid(score(u, pos) - score(u, neg))

Role: Baseline. If a fancier model can't beat MF, the added complexity isn't justified.

Model 2

LightGCN — Graph Neural Network

Key Idea

Users and items form a bipartite graph. LightGCN propagates embeddings through this graph — each node absorbs information from its neighbors.

// Layer-wise propagation
E(k+1) = D-½ A D-½ · E(k)

// Final = mean of all layers
Efinal = mean(E(0), E(1), E(2), E(3))

No feature transforms, no nonlinearities. Just neighborhood averaging — deliberately simple.

Why it wins: Multi-hop structure captures "users who liked similar items" transitively — 3 hops deep.

↓ D-½AD-½

My Contribution

Feature-Gated LightGCN

Can side features improve graph-based recommendations?

Design

Take LightGCN's efficient graph propagation. Add projected side features. Let the model learn how much to trust each signal via a sigmoid gate.

// Graph path (LightGCN)
E_graph = mean(E(0), ..., E(3))

// Feature path
u_feat = Linear(user_features)
i_feat = Linear(item_features) + Linear(text_emb)

// Learnable gate
gate = sigmoid(learnable_param)
E_final = (1-gate) * E_graph + gate * features

18%

The model decided: graph signal is 4.5× more important than features.

Takeaways

Key Findings

1. Graph structure wins on sparse data

LightGCN (0.729) beats all feature-enriched models. Multi-hop neighborhood averaging captures collaborative signal that content features cannot replicate. Feature-Gated LightGCN's learned gate confirms: 82% graph, 18% features.

2. Text embeddings help modestly (+2.6%)

Adding item titles via SentenceTransformer improved Two-Tower from 0.619 to 0.636. But rich text (descriptions + features) actually hurt — noise overwhelms signal on sparse data.

3. Cold-start needs a different architecture

The best-accuracy model (LightGCN) cannot serve new users. Two-Tower trades 12% accuracy for the ability to recommend from 3 browsed items. In production, this tradeoff is always worth it.

4. Loss function matters more than features

BPR collapsed the Two-Tower model (0.23). InfoNCE with temperature scaling is essential for dual-encoder training. The same model with the wrong loss is 3× worse.

Bottom line: There is no single best model. LightGCN for accuracy, Two-Tower for production serving, and the ablation study tells you why each component helps or hurts.
